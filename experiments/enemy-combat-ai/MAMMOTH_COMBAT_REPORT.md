# マンモス攻撃と既存戦闘処理の接続実験

2026-11-01。Node 25.3.0、esbuild、既存distを使用。対象本体はmain `b67204704486ff15caac5392206f319a45446b94`。本体ソースは変更しない。

## 実行と結果

依存導入後、リポジトリルートで実行する。distがなければ先に `node scripts/build.mjs` を実行する。

```sh
node experiments/enemy-combat-ai/mammoth_combat_test.mjs
node --test tests/mammoth-ground.test.mjs tests/riding.test.mjs tests/riding-server.test.mjs tests/hunting.test.mjs
```

追加接続試験16項目成功。既存の地形・騎乗・狩猟回帰23件成功。Nodeは指定系列とは異なる。結果を `mammoth_combat_results.json` に保存する。

`shared/combat.mts` の実ソースを一時bundleし、非公開の `applyHit` と `clearLine` を試験用にexportするだけで本体の実装は変えない。射程・攻撃角・遮蔽は既存関数、HP・怯み・封印・死亡は既存applyHitを使う。移動は実際のCollisionWorldとmammothNavigationを使う。攻撃開始・予備動作・護衛距離制限を小さな実験アダプターで追加する。

## ボス戦で見つかった接続不足

実applyHitは `provokedBy` にマンモスIDを記録する。しかし既存の `provoker` と巨獣AIはプレイヤー集合から対象を引くため、マンモスIDが消費されても反撃対象にならない。実験ではこの不成立を明示的に再現した。16項目の成功にこの問題の解消は含まれない。

ボス戦の味方として正式導入する前に、以下が必要。

- ボスの対象候補を生存する仲間動物へ拡張し、動物のhealthとプレイヤーのenergyを区別して反撃を接続する。
- 攻撃者本人のヘイトを記録する。テイムしたプレイヤーへ自動転嫁しない。
- 現applyHitはplayerDamageScale等のプレイヤー向け調整を使う。味方動物へ同じ調整を適用するか別にするか決める。
- 複数頭の連打で怯み続ける可能性を検証する。無償の一方的攻撃や怯み拘束を成功扱いにしない。

## テイムと集団戦の方針

テイムは仲間意識。マンモスは仲間になる難易度を高くする方針とし、なった後は前衛・護衛・敵の注意を引き受ける味方を目指す。ただし注意を引く効果は現行コード未対応。信頼形成に時間や複数の適切な行動を要する案を候補とし、条件・成功率・必要回数は未決定。騎乗できることだけで仲間関係が成立したことにしない。

子連れは子どもの護衛を優先し、ボス戦へ無条件に追従しない。仲間への援護でも護衛可能な範囲を超えない。騎乗中の自律攻撃は中止する。死亡・離脱・回復・再出現・仲間関係の保存と、ボス戦への参加条件は別途設計する。

## この実験が確認していないこと

- 常設のゲーム更新ループへの組込みではなく、既存関数へ接続したローカル実験。本体の攻撃モーション・描画・通信は未接続。
- 護衛対象は試験で指定する。仲間リストを試験に付けているが、そのリストから援護対象を選ぶ自動判断や信頼獲得は今回のアダプターにない。
- 子どもは実animalの複製に試験用位置と半径を与えている。幼体の正式なモデル・成長・親子認識ではない。
- 護衛と放牧を同時に回す仲裁は未実装。騎乗移動の比較は行ったが、護衛中の放牧更新との統合は未検証。
- 群れの役割分担モデルは今回の実コード試験へ未結合。ボス戦の勝率、反撃、全地形、性能、マルチ同期を実証していない。
- 体当たりはマンモス自身の衝突移動まで。敵の押し出しは未実装。2頭の試験はダメージ計上のみで、実戦の隊列や接触回避の検証ではない。
- 既存のstartAttack/resolveAttack全体を流用したのではない。プレイヤー専用の開始条件・対象選択を避け、共通化可能な命中と損害の関数を接続した。
