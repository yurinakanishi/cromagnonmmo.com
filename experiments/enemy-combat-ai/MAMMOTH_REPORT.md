# マンモス：子どもの護衛・群れの援護・テイムの仲間関係

2026-11-01。現行main `b67204704486ff15caac5392206f319a45446b94` を調査。今回の追加条件は「テイムは仲間意識とする」。所有権や命令への絶対服従を意味しない。

## 現行実装で確認したこと

- `shared/scenery-scatter.mts` は狩猟地点ごとにマンモスを生成し、異なるscaleを与える。小さい個体を子どもと定義する属性や親子関係は見当たらない。
- `shared/animals.mts` は放牧・草を食べる動き・被弾停止・安全な地形への移動を扱う。`age` は行動周期に使う経過値であり、生物学的な幼体判定ではない。群れの防衛攻撃はない。
- `shared/riding.mts` は近接・生存・空席・硬直などを確認して騎乗を許可する。恒久的な仲間関係を条件にはしていない。騎乗中の移動はプレイヤー操作が優先され、降りると現在地点を放牧のhomeにする。
- `tests/riding.test.mjs` は騎乗中の狩猟対象除外なども確認する。騎乗者IDをテイム・仲間IDとして代用しない。

これは調査したコード上の事実であり、ユーザーが述べたテイムの概念を否定するものではない。以下でその意味を「個体間の仲間関係」として具体化する。

## 追加案

群れID、幼体フラグ、護衛担当、個体ごとの仲間IDを、既存の騎乗状態とは別に持つ。テイムしたプレイヤーも援護対象になる。1頭との仲間関係を群れ全体へ自動複製しない。仲間関係は種族を越えて持てるが、子どもの護衛を放棄する理由にはしない。

成体を護衛と援護に分ける。護衛は子どもと脅威の間へ入り、援護役は近い攻撃者へ向かう。子どもから離れすぎた攻撃者は追わず帰還する。護衛役は一度決めたら保持し、死亡・騎乗などで担当できなくなった場合だけ再割当する。接近だけなら警戒し、確認した攻撃と区別する。仲間が子どもを攻撃した場合も防衛はするが、それだけで永続的な仲間関係を削除しない。関係変化の規則は未決定。

社会性ベクトルによる優先度調整を導入する場合も、護衛を残す条件を単なる加点だけにしない。今回の試験は役割と距離制約に絞ったもので、社会性ベクトルや人格SDPは未接続。

## ローカル試験

```sh
python3 experiments/enemy-combat-ai/mammoth_herd_test.py
node --test tests/mammoth-ground.test.mjs tests/riding.test.mjs tests/riding-server.test.mjs tests/hunting.test.mjs
```

Python標準ライブラリの独立モデル13件成功。出力は `mammoth_herd_results.json`。既存実装の対象回帰テスト23件も成功、スキップ0。後者は前回直接ビルドした同じ本体ソースのdistを使用。Node 25.3.0は指定系列とは異なる。既存のriding-server試験はローカルで複数接続を動かすが、新しい護衛モデルの同期試験ではない。

| 条件 | 確認結果 |
| --- | --- |
| 子どもへの攻撃を知った同族 | 1頭が護衛、別の成体が援護に接近 |
| 成体の仲間が攻撃される | 護衛を残して援護 |
| 攻撃者が80ステップ逃走 | 護衛は毎ステップ子どもから2単位以内。援護役も追撃を打ち切り帰還 |
| 成体が1頭だけ | 追撃せず護衛を継続 |
| 子どもが40ステップ退避 | 護衛が追従し2単位以内を維持 |
| 別一族・通知を受けない個体 | 無関係な相手への援護攻撃を開始しない |
| 接近だけ／仲間の接近 | 未知の相手には警戒。仲間には警戒を抑える。接近だけで攻撃対象にしない |
| テイムした仲間への攻撃 | 援護するが子どもの護衛を維持。遠くへの追撃は打ち切る |
| 騎乗 | 操作・位置を上書きせず、別の成体へ護衛を割当。騎乗だけでは仲間関係を生成しない |
| 護衛死亡 | 生存する成体へ再割当 |
| 唯一の成体が騎乗中 | 護衛不在を明示。保護できたとは扱わない |

最初の試験では毎回「最も近い成体」を選び直し、帰還役と護衛役が交替して移動が不安定になった。護衛の継続割当へ変更して再検証した。

## 限界・残る仕様判断

- 群れごとに子ども1頭の平面上の点モデル。身体半径・衝突・崖・攻撃アニメーション・損害は扱わない。実際の巨体の間合いに2単位をそのまま適用しない。
- 脅威は1人、仲間への攻撃通知と相手位置は人工入力。感覚モデルとの接続、通知の期限、複数脅威・複数幼体は未検証。
- 子どもの退避は試験入力で、子ども自身の逃走AIはない。護衛できる速度と初期距離の範囲で確認しただけで、任意の配置・速度では保証しない。
- 仲間関係は手で与える集合。関係の獲得・喪失・保存・共有、テイムの操作UIは未実装。
- 全成体が死亡・騎乗中なら護衛は作れない。騎乗を禁止するか、警告するか、子どもが同行するかは別途決める。今回の試験は既存の騎乗操作を維持する案。
- 降車時のhome変更と親子の再合流の関係も要設計。モデルは既存ゲームに組み込んでおらず、回帰23件の成功は新モデルとの非干渉の証明ではない。
- 群れの新規配置、実ゲームの戦闘・マルチ同期・バランスは未検証。本体ソースは変更していない。

## 共通設計としての撤退ルール追加

子どもの喪失を群れの持続状態として扱う。生存幼体がなくなった途端に追撃制限が外れる旧実験の不具合を修正した。群れモデルは現在16件成功。死体除去後も撤退し、仲間への援護より優先し、別群れは巻き込まない。撤退先は仮の(-10,0)。騎乗中は撤退待ちで操作を維持し、降車後に移動する暫定案。保存復元、撤退解除、死亡の認知伝播は未実装。子どもの短い牙・低い攻撃力と耐久力は設計要求で、数値・モデルは未反映。
