## 方法と結果

本体の `shared/violet-behemoth.mts` を読み、無変更版と、攻撃選択直前に小さなフックを追加した版を一時ディレクトリでbundleして比較する。本体ソースは編集しない。フック位置が変わった場合は停止する。終了時に一時bundleを削除し、`behemoth_results.json` に成功項目を保存する。

フックは既存の `begin` と攻撃実行処理を使う。実行中攻撃、怯み、帰還、回復待ち、新規捕捉による突進を既存コードに処理させ、その後の選択機会だけ利用する。対象IDや `provokedBy` は書き換えない。射程・遮蔽・毒のクールダウンに合わない要求は既存選択へ戻す。近接の交互選択カウンター更新も維持する。

| 検証 | 観測結果 |
| --- | --- |
| 尾が有効という経験を反復 | 尾攻撃を選択 |
| 次に噛みつきが有効という経験へ変更 | 噛みつきへ再適応 |
| 次に毒が有効という経験へ変更 | 遠距離候補の中から毒を選択 |
| 次に突進が有効という経験へ変更 | 突進へ再適応 |
| 学習結果を実際の攻撃選択へ接続 | 尾攻撃を開始。途中で評価が変わっても完遂し、回復後に噛みつきを開始 |
| 4種類それぞれで従来と同じ攻撃を選択 | 25ms刻みで、位置・向き・攻撃状態・予備動作・命中時刻・損害・飛翔毒・回復待ちを含む状態が無変更版と一致。各攻撃の実命中1回と設定どおりの損害も確認 |
| 攻撃中・回復待ちに別攻撃を要求 | フック呼出し0回。進行は無変更版と一致 |
| 射程外の噛みつき・尾、近すぎる毒 | 不適合な要求を採用せず既存選択と一致 |
| 怯み・縄張り外・無敵保護・被弾通知・毒の待ち時間・遮蔽 | 各条件の比較時点で既存処理と一致 |

学習は攻撃別の成否の指数移動平均（学習率0.25）と最大0.08の加算補正。固定の基礎優先度に加えて候補を比較する。今回の実験では人格SDPを再実装せず、学習補正と接続位置に範囲を絞った。経験を変える各段階で、全攻撃に人工的な成否を16回ずつ与える。これは探索方策や実戦からの報酬抽出ではない。

## 分かった問題と修正

最初の比較では、フックが近接の交互選択カウンターを更新せず差分が出た。実験フックを修正し、既存選択に戻った際の順番に影響しないようにした。また、毒の実行に必要な障害物問い合わせを平面fixtureへ追加した。合格まで比較対象の内部状態を除外することはしていない。

## 限界

- 「背後から攻められた」「遠距離攻撃を受けた」という意味付けと成否は試験入力。動作からの認識、実際の被害からの報酬抽出、未知の戦術への汎化は未検証。
- 衝突環境は平坦な簡略fixture。既存39件は元の実装に対する別の回帰確認であり、フックを全39件に注入した検証ではない。
- 22項目の比較範囲で非干渉を確認したもので、全状況の証明ではない。既存の被弾による攻撃中断は維持する。
- 巨獣の対象切替・多人数ヘイト、感覚モデル、一族共有、学習の保存復元とは未結合。嗅覚や仲間の増設はしていない。
- 初回捕捉の突進は既存処理を維持するため学習対象の選択点に含まれない。
- 描画、実マップ全体、ネットワーク同期、実戦バランス、性能は未検証。
